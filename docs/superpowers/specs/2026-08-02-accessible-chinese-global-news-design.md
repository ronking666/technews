# 中文可访问的全球科技新闻来源设计

## 背景与根因

上一轮新增的 Hacker News、Ars Technica、TechCrunch AI、
MIT Technology Review AI、OpenAI 和 Google AI RSS 提高了全球新闻覆盖，
但它们直接输出英文标题，部分文章域名在中国大陆移动网络中访问不稳定。
早报的原始新闻区块没有逐条翻译，因此即使 DeepSeek 总摘要为中文，用户仍无法方便地
阅读每条新闻。

## 目标

- IT之家、少数派、爱范儿三个原始来源保持名称、URL、顺序和行为不变。
- 只替换上一轮新增的六个英文来源。
- 替代来源必须输出中文标题，并以中国大陆通常可直接访问的中文科技网站为文章链接。
- 内容范围仍覆盖全球 AI、软件、科学、安全、创业和科技产业新闻。
- 不增加翻译 API、模型调用、依赖、Secret、工作流权限或 Server酱发送次数。

## 方案比较

### 方案 A：保留英文来源并用 DeepSeek 翻译标题

可以保留一手英文信息，但文章链接仍可能无法访问；每日报告还会新增翻译接口依赖、
延迟和失败路径。即使翻译成功，也无法解决点击后打不开的问题。

### 方案 B：同时保留中英文来源

覆盖最广，但会显著增加报告长度和重复内容，手机阅读体验更差，也可能超过 AI 摘要
输入上限。

### 方案 C：替换为中文全球科技媒体（采用）

将刚新增的六个英文源替换为：

| 来源 | RSS URL | 主要覆盖 |
| --- | --- | --- |
| 雷峰网 | `https://www.leiphone.com/feed` | 全球 AI、大模型与产业 |
| 极客公园 | `https://www.geekpark.net/rss` | 全球科技公司与产品 |
| InfoQ中文 | `https://www.infoq.cn/feed` | 全球软件、开发与企业 AI |
| Solidot | `https://www.solidot.org/index.rss` | 全球科技、科学、安全与开源 |
| 36氪 | `https://36kr.com/feed` | 科技公司、创业与商业 |
| 钛媒体 | `https://www.tmtpost.com/rss.xml` | 全球科技产业与商业 |

这六个来源的 RSS 均能被现有解析器读取；实测每个来源第一篇文章均返回 HTTP 200，
标题均为中文。雷峰网实测首条为
“从翻译到桌面Agent，网易有道全线产品完成DeepSeek-V4-Flash正式版升级”，
能覆盖本次用户指出的漏报主题。

## 配置和数据流

仅修改 `config.toml` 中第四至第九个 `[[news.sources]]`：

- 删除上一轮六个英文来源表项。
- 在相同位置写入六个中文替代来源。
- 不修改前三个来源、`items_per_source`、去重、关键词、报告渲染或推送工作流。

现有数据流保持：

`RSS -> parse_rss -> NewsItem(中文标题, 国内文章链接) -> 去重/高亮 -> Server酱`

## 测试与验收

- 配置测试继续精确断言前三个原始来源完全不变。
- 配置测试断言后六个来源精确等于中文替代集合。
- 真实 smoke test 抓取九个来源，每源至少一条；后六个来源的标题必须包含中文字符。
- 对后六个来源的第一篇文章执行只读 GET，必须返回 HTTP 200。
- 运行完整 pytest、Ruff、格式、编译、敏感信息和工作流差异检查。
- 不手动触发科技或财经早报，不消耗额外 Server酱额度。

## 风险与处理

中文科技媒体属于二次报道，极少数全球首发可能比官方英文源稍晚；作为交换，用户能直接
阅读中文标题和文章。单个来源发生反爬或 RSS 变更时，沿用现有失败隔离，其他来源继续
发送并在失败来源区块显示“获取失败”。
