# TechNews 手机排版与提前推送设计

## 目标

改善 Server酱手机页面中财经指标挤成连续段落的问题，并在不减少新闻源、新闻条数、行情标的和行情历史范围的前提下，让两份早报更早送达。

## 延迟诊断

2026-07-17 的 GitHub Actions 记录显示：

- 科技任务配置为北京时间 05:30，实际到 06:30:16 才创建，06:30:54 完成。
- 财经任务配置为北京时间 06:15，实际到 07:09:58 才创建，07:10:25 完成。
- 两个任务从 runner 启动到完成都不到一分钟，且 Server酱接收时间与任务完成时间一致。

因此根因是 GitHub `schedule` 事件排队约 55–60 分钟，不是采集、Python 代码或 Server酱发送耗时。GitHub 官方也说明定时事件在高负载时可能延迟，建议避开高负载分钟。GitHub 定时任务仍然不是实时调度器，本次优化只能降低和吸收延迟，不能承诺精确到分钟。

## 方案比较

### 方案 A：固定 UTC 整体前移

改动最少，但财经任务无法自动适应美国夏令时；冬季可能在美股收盘前运行，影响数据完整性。

### 方案 B：时区感知调度（采用）

科技任务直接使用 `Asia/Shanghai`，财经任务使用 `America/New_York`。财经始终在纽约 16:00 收盘后运行，自动适配夏令时。分钟数避开整点，并整体前移以吸收 GitHub 排队时间。

### 方案 C：主任务加备用任务

可降低任务被丢弃的风险，但需要持久化去重状态，否则会重复推送并消耗 Server酱额度。当前项目不引入这层复杂度。

## 调度设计

- 科技早报：`cron: '27 4 * * *'`，`timezone: 'Asia/Shanghai'`，目标北京时间 04:27。
- 财经早报：`cron: '47 16 * * *'`，`timezone: 'America/New_York'`。
  - 美国夏令时对应北京时间约 04:47。
  - 美国冬令时对应北京时间约 05:47。
  - 始终晚于纽约股市 16:00 收盘 47 分钟，避免固定北京时间前移造成冬季提前到收盘前。

调度只改变开始时间，不修改 RSS 来源、每源 8 条上限、去重规则、6 个财经标的、3 个月历史范围或失败重试，因此信息采集能力保持不变。

## 手机排版设计

### 财经报告

每个标的保持独立标题和分隔线，删除把多项指标串在同一个引用段落中的排版，改为每项独占一行的 Markdown 列表：

```markdown
### 📉 黄金（纽约期金）

- **数据日期**：2026-07-16
- **最新价**：**3981.70**
- **当日涨跌**：-62.30（-1.54%）
- **5日趋势**：-3.60%
- **20日趋势**：-8.06%
- **20日区间**：3981.70 ～ 4358.90
```

趋势窗口逐项显示，避免 `｜` 分隔内容在窄屏自动换行后失去对应关系。上涨、下跌和持平仍保留现有图标。

### 科技报告

来源标题与第一条新闻之间增加空行，每条新闻之间增加空行，不同来源之间加入水平分隔线。去重、关键词 `🔥` 和链接保持不变。

### AI 摘要

提示词要求输出 3–5 条 Markdown 项目符号且不重复标题，确保摘要在手机上也是一行一个重点。AI 失败仍回退到确定性原报告。

## 错误与兼容

- 失败来源和失败行情仍显示明确提示。
- 手动 `workflow_dispatch` 不受时区调度影响，仍可随时运行。
- 调度字段使用 GitHub 官方支持的 IANA 时区名称。
- 不增加真实推送测试，避免消耗 Server酱额度。

## 测试与验收

- 财经渲染测试验证每个指标是独立列表项，不再生成 `｜` 串联的趋势行。
- 新闻渲染测试验证条目和来源之间有稳定留白与分隔线。
- AI 测试验证新闻和财经提示词要求 Markdown 项目符号。
- 工作流测试验证新 cron、IANA 时区、原有 Secret、权限和手动触发均保留。
- 全量运行 pytest、Ruff、Python 编译、YAML 解析、Secret 扫描和 `git diff --check`。
